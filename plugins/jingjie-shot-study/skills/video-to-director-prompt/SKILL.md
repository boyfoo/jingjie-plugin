# 视频反推提示词

核心任务是“输入参考视频，输出可直接用于AI视频生成的提示词”。观察动作、镜头、光影和视听关系，是为反推制作输入提供依据；完成拉片报告不等于完成反推任务。

先理解视频表现什么、用户想保留或改变什么，再把人物与观众的情绪变化转译为分镜、动作、摄影、光影及参考图约束。保留导演判断和合理改编能力；以用户要达到的效果评价结果。反推提示词是根据画面整理的制作方案，不是作者原始提示词，也不默认逐帧复刻。没有改编要求时保留参考视频的核心内容与有效机制，显著改动应说明目的。

默认中文交流，沿用用户已确认的模型、资产策略、交付形式和审美选择。模型未知时先做通用方案，只在具体模型限制影响执行时查证或澄清。不要把某次案例的时长、镜头数、配色、题材和参考图数量写成通用标准。

## 按当前任务进入

- 视频反推请求：核验观察 → 提炼需要生成的内容与关系 → 结合创作目的取舍 → 写完整生成提示词与必要的参考图方案。
- 已有反推任务的新试片或修改意见：复用实际输入和已有素材，诊断问题并修正提示词或参考资产，不重做已经确认的全部分析。
- 反推过程中的局部咨询：回答当前问题；没有要求重写时，不自动重做全部提示词、图片或文件包。
- 输入版本不清：先查当前文件和对话。可继续观察，但将版本假设写明，不能据此断言“已写但模型没执行”。

本技能与拉片技能是两个独立任务入口，区别在目标和交付：

- [video-shot-study](../video-shot-study/SKILL.md)：视频 → 镜头与视听分析；解释已有视频怎么拍、怎么剪、怎么表达，并按需核验作者原文。
- [video-prompt-alignment](../video-prompt-alignment/SKILL.md)：视频＋既有要求文本 → 对应关系、实现情况与差异分析。
- 本技能：视频＋用户意图 → 可直接使用的AI生成提示词＋必要的参考图方案；可承接生成后反馈继续修正这些制作输入。

普通拉片、只分析拍摄手法或只核对文字是否实现时不进入本技能。只有反推/生成提示词的请求、明确调用本技能，或已有反推任务的延续，才进入本流程；只提供链接且意图不明时结合上下文判断，不自行认定为反推。反推可独立执行，不要求先完成拉片报告、取得作者原文、提交镜界或等待深入邀请。已有观察可复用，无需重复执行其他技能的整套流程。

按需读取以下文件：

- 核验视频、抽帧观察、选取或生成参考资产：[观察与资产](references/observation-and-assets.md)。
- 将分析转化为创作意图、分镜、光影、声音与提示词：[导演与提示词](references/directing-and-prompts.md)。
- 比较试片、保留成功内容、迭代以及交付HTML/TXT/图片包：[复盘与交付](references/iteration-and-delivery.md)。

## 1. 先建立可信观察

读取真实视频及必要元数据；能播放时看完整段，再核对重点。无法直接播放时，查看覆盖全片的帧和动作、切点附近的密集帧，并说明观察方式。抽了帧不等于已经看过；没有听到声音，不评价原片的声音细节。无法取得素材时说明缺口，继续可独立完成的工作，不用用户文字或少量静帧冒充完整观看。

区分三层：**原片观察**是画面证据，**我们的判断**是对效果和原因的解释，**我们的设计**是主动改编。可推测，但不能把推测写成作者意图、生成模型机制或原始提示词的事实。

内部保留准确时间基准以便寻帧；面向用户的秒数和提示词时间最多保留一位小数。原片时间用于定位，创作时长是另行分配的篇幅预算。证据截图和上传参考资产分别管理。

## 2. 先决定目的、关系和情绪，再决定镜头

从现有要求提炼：主体是谁，与对方/环境是什么关系，这段要完成什么，人物状态如何改变，希望观众先注意什么、随后感到什么。信息足够时直接提出明确方案，不为已有答案反复询问。

把参考片的有效机制与用户的新想法结合：保留有用的因果、节奏、质感或视觉母题；重新判断动机、位置、运动和观看逻辑是否成立。允许夸张与超现实，但同一世界内的规则要连续。

为每个镜头确定：

1. 进入时的状态、获得的新信息和离开时的状态。
2. 动作的触发原因、主要变化、可见结果与结束条件。
3. 景别、机位、构图和运动如何引导注意，为什么在这里切、停、遮挡或变速。
4. 光影、材质、环境运动及声音怎样支持这一变化。
5. 与下一镜如何接动作、方向、空间、明暗或声音。

安静镜头也可以服务观察、关系和情绪，不必强加冲突、运镜或高潮。所谓“酷”要落实为信息揭示、身体感受、节奏变化或视觉关系。

## 3. 把参考图当作有职责的制作输入

优先沿用用户当前选择的原片截图、重新设计资产或混合方案；只有确实需要时生成或修改图片。选择最少但足够的参考图，不以增加数量替代解决风格和构图冲突。

人物身份与特写细节需要分别控制时，拆成身体/服装设定和头部近景设定；同一角色保持一致。场景、物品、色彩和特效设定按实际作用配置。关键动作截图仅在有必要且符合用户选择时使用。

给每张图写清身份、约束内容和适用阶段。整幅动作图同时携带姿势、构图、光影和场景，文字“只参考某项”不保证能隔离其他影响。出现错阶段复用时，考虑替换资产、减少输入或分段时真正排除该图，不能只堆叠禁令。

本地文件名与引用一一对应，例如 `图片1.png` 对应 `@图片1`。保留已交付版本的编号；独立子包需要重编号时同步提示词和映射表。

## 4. 写模型可执行的制作提示词

采用“创作目标与整体风格 → 参考图职责 → 必要的全局连续规则 → 分镜”的顺序，输出可直接使用、无需回看分析的完整提示词。

- 时间作为篇幅与快慢的预算，遵守用户/工具的实际限制。镜头内部写动作完成点；慢动作写开始、结束和恢复正常速度的条件。新增内容要重新分配篇幅，不能机械塞进旧时长。
- 可以写“像跳舞、有律动”等方向词，同时写清重心、肩胯、脚步、视线与表情。分别说明人物位移、肢体运动和摄影机运动。
- 交代动作触发、动力、接触、反应和出镜状态。一个动作阶段只消费一次；特效扩散和对手反应可以延续，不能无意拖住已经完成的主体动作。
- 次级动态要有原因并服从主动作，例如转头后的发丝滞后、落脚的衣摆回落、接触后的水花。不要靠添加许多无关运动制造“真实”。
- 光影写来源、方向、明暗层级与受光表面；特效写来源、单元形状、路径、接触作用和衰减。多色效果应说明不同单元同时保留各自颜色，避免只剩抽象“彩色光”。
- 如设计声音，将同步点、变化与声音衔接写进实际制作提示词或独立声音交付，不只留在分析里。未听到原片的部分标为声音设计建议。

不要用“电影级、史诗、超高质量”等形容词替代明确画面关系，也不要把所有观察细节塞进每个镜头。保留影响结果的主导关系。

## 5. 用试片验证假设，保护已经成功的部分

比较可见结果与实际输入，分别记录：设计本身的问题、提示词遗漏或冲突、已写却未实现、参考资产可能干扰、新增创作要求。没有验证的生成机制只作为假设。

用户明确喜欢或要求保留的句段、资产和衔接列为锁定项；修改后与旧版实际对比。要求“这段不改”时保留原文，需要新增颜色等条件可在其外补充。未经讨论不要顺手改写成功片段。

先找到缺失或矛盾的关系，再决定修改文字、镜头、资产还是生成方式。连续失败时缩小到可以辨别原因的片段，准备可执行的小范围试验；分段必须提供各自的提示词、图片子集与出入状态，不能只建议“拆开生成”。

## 6. 交付与完成标准

收到视频反推请求时，默认交付完整、可直接使用的生成提示词，以及实际需要的参考图选择与用途。分镜和分析作为制作依据，不以镜头分析表代替最终提示词。用户只追问局部原因或要求修改某段时，按该范围交付；用户明确暂停制作时不强行生成全文。

需要实际图片时交付与提示词引用对应的文件；需要图文报告时，HTML在提示词上方展示相应图片、编号和用途，配套TXT与上传包保持同一版本。不因反推请求自动增加无关的完整拉片报告、评分或镜界提交。

遵守任务目录的命名规则。只做当前已授权的本地工作；生成方案不等于授权外部提交、发布或付费试片。不要因为借鉴了其他拉片方法就自动修改插件或上传镜界。

结束前核对动作与空间衔接、参考图阶段、文件名与引用、锁定内容以及各交付版本的一致性。说明实际检查了哪些内容；文件校验通过不代表生成效果已经验证，未获得新试片时不声称问题已解决。
