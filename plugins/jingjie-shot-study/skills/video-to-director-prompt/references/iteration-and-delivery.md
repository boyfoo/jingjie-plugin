# 试片复盘、受控修正与交付

用于用户给出新结果、指出缺陷、要求局部修改，或需要最终HTML/TXT/上传包。评价目标是本次创作目的与用户认可的效果，不是机械计算与原片的差异。

## 先核对实际输入

记录试片文件、提示词版本、实际上传的图片及模型/设置中与问题相关的部分。先查已提供信息，缺失时再简短澄清；观察画面可以并行进行。尚未确认的输入以假设标注，不能当作确定因果依据。

保持三个独立基准：原片提供学习素材；用户确认的制作输入表达本次目标；试片是待检验结果。不能从试片反写要求再宣称完成，也不能把与原片不同自动判为失败。核对要求时保留条件、因果、先后顺序和程度；出现了几个相同元素不等于它们之间的关系成立。

结合连续帧或播放记录看动作过程；需要时保留对比帧。对比同一事件阶段而非只用同一秒数，不能把姿态与机位都不同的画面对齐后据此证明材质优劣。

可以用简表整理：可见现象及时间 → 实际输入依据 → 判断类别 → 最小修改 → 保留项 → 下轮验收。至少区分以下情况：

| 类别 | 判断与应对 |
| --- | --- |
| 设计逻辑有问题 | 即便严格执行文字也不成立；先改因果、空间、观看关系 |
| 提示词遗漏或自相矛盾 | 补缺失关系，消除互斥要求和重复动作阶段 |
| 已写但结果未实现 | 不再声称“缺少描述”；简化主事件、改变资产范围或试验生成方式 |
| 参考资产可能干扰 | 对照图像携带的姿态、构图、光影，必要时隔离输入验证 |
| 新增创作要求 | 重新设计相应部分，别误写成模型没执行旧要求 |

相似构图在错误阶段重现，可以确认其可见相似性；不能仅凭这一点断言模型的注意力、权重或内部机制。将“观察到的现象”和“可能的原因”分开。用户喜欢的合理新动作即使不在原片也可保留。

评价覆盖范围要匹配要求：“每步出现”需检查相关每一步，“全程一致”不能靠一个成功特写确认。一次清楚的反例可指出局部偏差；稀疏抽帧没发现问题，只能说已查看范围未见。区分未检查、无法判断、部分实现和明确偏离。也解释成功段落中有效的因果、动作或声画关系，作为后续保留依据。

## 怎样停止盲目增加文字

先确定要验证的关系，选择匹配的改法：

1. 设计问题先改动作与镜头逻辑；缺少结束条件就明确什么时候结束。
2. 字面不清或冲突时局部消歧，不把所有镜头加长。
3. 已明确但仍失败时检查一次承担多少事件、动作图是否冲突、输入是否超出已知能力；优先让主事件可执行。
4. 连续几版仍失败时提供更小且可区分原因的试验：固定其余输入，只调整正在检验的因素，或明确本轮同时改了哪些因素，不能称为单变量验证。
5. 只有用户实际生成并回传，或明确授权代为试片后，才能评价生成结果。文件内容检查只能验证交付一致性。

需要拆段时，产出每段可直接使用的提示词、确实需要的图片子集、入镜/出镜状态和拼接方法。造成干扰的图片应实际不在该片段包中，不能一边保留上传一边要求模型完全忽略。拆段是否值得取决于一致性、动作连续性与工具成本，不默认每镜单独生成。

拼接检查姿态、屏幕方向、位置尺度、曝光与声音；遮挡、运动匹配或声音延续可以帮助连接，但不能保证独立生成的两段自然连续。

## 锁定已经有效的内容

每轮修订前从用户明确反馈和现有版本提取保留项：成功句段、图片、动作衔接、节奏或光影。保留用户明确指定的原文，不用“意思相同”的改写代替；新增条件可放在锁定段之外。

修改后实际与上一版对比，确认这些内容未漂移。需要更换被锁定的依赖时说明冲突，不能静默扩大范围。图片需要精确保持时可核验哈希。

历史版本保留，当前入口指向明确的最新版；只修改需要变化的部分。不要因全局重写意外丢掉局部颜色、动作结束点、参考图用途或成功的衔接。也不要为了修正文档自动重做所有图片。

下轮验收写可观察结果，例如“旋转完成后收腿进入下降，不继续侧旋”“冲击传播到对手位置后才出现受力反应”。不能用提示词里出现了某个词当作效果达标。

## 按需求交付

分析性问题可用简洁结论与证据直接回答；需要实际制作时，按复杂度给出：创作取舍、情绪/信息变化、分镜、参考图映射、完整提示词。需要本地制作包时再生成HTML、TXT和图片/压缩包，不把文件数量当作工作质量。

图文报告要求：

- 图片位于提示词上方，清楚标识 `@图片N`、对应文件名及用途；分析证据与上传图分区。
- 提示词可以直接复制，内容自足；不要让用户自行拼接散落修正。
- 当前完整版本与单段试验标识清楚，避免把独立片段的重编号用于全片。
- 最好从同一份内容生成HTML、TXT和上传包，检查实际文字一致，避免只改了页面说明。
- 不默认加新资产补所有问题。文件名与图片序号一一对应，旧版本映射保持可追溯。

资产清单可使用表格或JSON。根据需要记录 `id`、`filename`、`source_kind`、`source_time`、`role`、`shot_scope`、`sha256`，不适用的字段省略；生成资产不能填成原片截图。

## 完成前核对

核对实际输出而非只检查写作计划：

- 图片存在、可读取、格式正确，提示词中的每个引用有对应上传文件。
- HTML、TXT、上传包中的提示词和编号属于同一版。
- 时间展示不超过一位小数；新增镜头后的篇幅仍符合已知限制。
- 每镜输入/输出状态相接，无意外动作重复、动力断裂或错误阶段复用。
- 用户指定不改的文字、图片和成功衔接保持原样。
- 新增声音、光影与动作要求已进入实际制作文本，不只写在分析说明。

遵守项目目录命名规则，不把来源下载链接中的签名令牌或其他凭据打进公开包。检查HTML源码或打开文件不等于已完成浏览器视觉验证，报告实际做到的检查范围。

最后简要说明修改了什么、保留了什么、下次试片具体观察什么；尚无新试片时明确效果待验证，不承诺模型一定执行。
