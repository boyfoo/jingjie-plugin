# 镜界 MCP 分模块保存与修改

用户要求按镜界体系归类时，可以只读查询当前分类库。本文件的创建、上传和写入步骤仅在用户授权相应操作时执行；修改 skill、讨论流程或只做拉片，不授权创建或改动案例。一个视频对应一个案例；各模块直接保存编辑稿，发布由用户在网站操作。

## 1. 发现当前契约，读取分类体系

- 先发现当前工具，读取 MCP 资源 `jingjie://submission-guide`，再调用 `jingjie_get_taxonomy`。工具参数、限制和字段规则以当前返回为准，不沿用旧的整案导入或万能 patch 结构。
- 用户要求保存或按镜界体系归类时，在观察与整理资料前读取类型、分组及选项、`caseFields`、`shotFields` 和 `rules`，据此区分固定选项与自由文本。若先完成拉片才收到提交要求，复用画面记录，读取体系后再做映射，不必重做观察。
- 分组选项保存 `option.value`；`option.id` 用于标识，`option.label` 用于显示，不用它们代替 value。镜头固定字段使用 `shotFields` 中对应字段的合法字符串；不要直接拿案例分组选项替代镜头字段自己的选项集。
- 分类库的 `revision` 与案例的 `revision` 含义不同，不可互换。库有分页时读完相关页；分类值被拒绝或发现库发生变化时重新读取。
- 没有分类读取工具时检查可用资源及模板。仍无法获取就明确说明缺口，保留已有值、省略无法核实的归类，不猜 ID、不从写入参数推断可选项、不用空数组代替未知项；其他已授权模块可继续。不要把未归类案例称为已完整交付。

## 2. 默认执行顺序

新案例按下表录入。已有案例先读本次涉及的内容，直接修改相应模块，不重新创建、不重传未变媒体。每步保存后按第3节回读核对，并使用当前案例 revision。

| 顺序 | 工具与操作 | 保存内容、依赖与回读 |
| --- | --- | --- |
| 1 | 读取流程指南与 `jingjie_get_taxonomy` | 在分析、整理前取得字段规则和当前分类体系；只修改提示词时不顺带重新归类。 |
| 2 | `jingjie_create_draft`，或复用已有 caseId | 新建传 `{requestId,kind,title?}`，kind 为 `video` 或 `image`；保留返回的稳定 caseId、revision 和入口。已有案例先 `get_draft(section:"summary")`。 |
| 3 | `jingjie_presign` → PUT → `jingjie_save_media_info` | 上传主素材，保存公开 src／image；视频保存真实 durationSeconds 及已知 metadata。带时间的提示词和镜头依赖已保存的真实视频时长。回读 `media`。 |
| 4 | `jingjie_save_prompt` | 完整原文、前文、时间行、后文四字段整组保存；回读 `prompt` 逐字核对。时间行独立于镜头，优先完成提示词模块。 |
| 5 | 逐条 `jingjie_save_shot` | 一个镜头一次：时间、首尾帧、画面资料、分析、叙事、声音、台词、转场、来源镜头提示词，以及已核实分类。回读 `shots` 并指定 itemId。人物未建时先省略 subjects。 |
| 6 | `jingjie_save_case_info` | 标题、简介；只传本次需修改字段，回读 `case_info`。 |
| 7 | `jingjie_save_analysis` | 案例整体分析，独立于逐镜分析；回读 `analysis`。不加入整篇统计、质量检查或审核字段。 |
| 8 | 逐条 `jingjie_save_cast_member` | 一个人物一次：稳定 id、名称、图片、备注；回读 `cast` 并指定 itemId。没有人物资料时不虚构人物。 |
| 9 | `jingjie_save_classification` | 按当前体系保存案例 type、tags、tagValues、emotion、lighting、movement，回读 `classification`。只选择有画面或可靠来源依据的项。 |
| 10 | 按需补充 `jingjie_save_shot` | 用同一镜头 id 补人物 subjects 或尚未完成的分类；人物 ID 必须已存在。已随镜头保存且核对的分类不重复提交，也不建立第二套画面分类。 |
| 11 | `jingjie_get_draft(section:"summary")` | 核对最终版本、状态、镜头／人物数量及模块完成情况；有差异再读相应区块，不默认回读整案。无需最后一次大提交。 |

这是完整新案例的默认顺序。资料尚未取得时明确记录未完成模块，继续其他满足依赖且已授权的操作；不能为填满步骤编造资料。仅改一个模块时不机械执行整套流程。镜头和人物图片可按需要另批上传，不必在创建前上传全部图片。

## 3. 保存契约、版本与工作记录

`save_*` 使用 `{caseId,revision,data,source?}`，不能直接把本地原始 `shots.json` 当作 data。成功返回 module、savedFields、clearedFields、warnings、新 revision 等回执，不返回完整草稿。

- 同一案例的各模块共享 revision。保存应顺序执行：上一操作成功 → 保留新 revision → 回读目标内容 → 以回读所得当前 revision 执行下一操作。不要并发写不同模块；独立素材 PUT 可以并发。
- `get_draft` 默认只读 summary，返回 `data` 与 revision。通常按目标 section 读取，`shots`、`cast`、`source` 可用 itemId 限定单条。译文须用 `get_draft({caseId,section:"all"})` 读取 `data.promptTranslation`；`section:"prompt"` 只有原文，summary 不含译文。此读取方式适用于修改前、保存后及超时／冲突恢复时。其余内容仅在确需全量资料或无法定位差异时使用 all。
- 除整组提示词外，省略字段表示保留；空字符串或 [] 明确清空。metadata 单字段 null 清除参数；未知音轨情况应省略，不能写成 false。
- 镜头 facts、镜头及案例 tagValues 按键合并，其他数组整体更新。修改一个分组时带齐该组应保留的值；修改 analysis 或 subjects 时带齐该对象目标数组，不用只追加一项的数组覆盖旧内容。
- 镜头和人物按 `data.id` 新增或修改，沿用稳定 ID；`position` 为从0开始的最终位置，省略时保留原序，新条追加。保存单条不会替换其他镜头或人物。
- 本地保留案例 caseId、最新 revision、模块／对象 ID、本次目标内容及保存回执。新建 requestId 与各上传批次 requestId 分开记录；submissionId 是上传批次 ID，不是 caseId。
- 原帖地址、原始资料、完整性限制和观察依据放入对应模块的私有 `source` 或本地记录。source 不进入公开案例或 Sites 导出，也不能替代实际编辑稿字段；不把来源解释追加进作者原文。

## 4. 素材上传与恢复

先检查路径、真实字节数、类型与 MIME。每个上传批次生成并保留 requestId；files 为 `[{localName,kind,mime,size}]`，localName 是输出目录内唯一相对路径。数量和大小限制以当前指南为准，不上传无关文件。

使用返回 uploadUrl 以 PUT 发送原始文件字节，原样携带 headers（含 public-read）；不用 FormData，不传路径或 URL 文本作为正文。确认 PUT 成功后，才在媒体、镜头或人物模块引用公开 mediaUrl。uploadUrl 只用于上传，不充当永久素材地址或原始来源。

中断后先 `jingjie_get_submission_status({submissionId})`：uploaded 跳过，awaiting_upload 继续上传，unavailable 保留标识稍后查询，invalid 按原因修正素材并用新 requestId 申请，禁止覆盖原对象。地址过期时沿用原 requestId 和相同 files 调用 presign；改变清单须新批次。旧批次中的首次保存结果是历史记录，当前案例状态和 revision 仍须 get_draft 获取。

新建结果不确定时，沿用创建 requestId 与相同参数重试以恢复同一案例；不要换 ID 重建。修改或补充资料复用 caseId 和现有媒体。替换视频 src 会重置旧时长与媒体参数，应同时提供新视频真实 durationSeconds 和已知 metadata；旧时间若超出新视频范围，先核验并调整受影响提示词或镜头，不能自动缩放、截断或沿用旧测量值。

## 5. 提示词整组保存

内容提取、来源与时间规则见 [SKILL.md 第4节](../SKILL.md#4-核对提示词及其时间段)。`jingjie_save_prompt.data` 四字段均必填，创建与修改层级一致：

| 字段 | 内容 |
| --- | --- |
| prompt | 已核实的完整原文。 |
| promptPrefix | 前文。 |
| promptLines | 时间行 `[{start,end,text}]`。 |
| promptSuffix | 后文。 |

- 不分四次写，不逐行保存时间提示词。修改已有提示词前先读 prompt 区块，组装四字段完整目标值；未修改部分沿用当前值，不能用空值占位而清空已有资料。只补前后文时也保留全文与时间行。
- 新案例确实无资料的部分才用空字符串或 []；无明确时间的原文仅放 prompt，其他三部分为空。图片也只允许 prompt，其余为空。只有片段时明确来源和完整性限制，不把片段描述成完整作者原文。
- 四字段不会互相自动生成，整组写入须核对内容对应性；旧案例缺少前后字段不代表原文没有这些内容。时间校验使用已保存的真实视频时长。
- 分界不清或有无法归属的无时间文字时保留全文并说明拆分限制，不静默挪动、吞掉末尾约束或相关空白。不混入页面按钮、助手分析或未经核实的复现提示词。
- 作者时间与实际时长不一致时先回查素材版本。仅在确认微小尾部差异且任务包含播放对齐时处理映射终点；仍遵守主文件的原文保留和时间精度规则。
- 保存后回读 prompt，逐字比较全文、前文、后文及每行 text，核对全部起止时间与数量；不能只核对总长度或行数。页面切换、高亮、跟随滚动须另行实测，接口保存成功不证明页面行为已验证。

### 5.1 用户确认后的中文译文保存

翻译时机与授权范围统一按 [SKILL.md 第6节](../SKILL.md#6-非中文提示词的翻译与保存)判断。译文使用独立字段，原文完整保留，不能把中文译文称为作者中文原文。仅要求翻译时按以下内容规则交付；写入镜界须有保存授权。

1. 核对本次翻译的完整来源。保存到已有案例时，发现当前 MCP 契约，读取 `get_draft(section:"prompt")`、对应 `source` 和最新 revision；修改已有译文前，另按第3节读取译文，保留本次未改部分。复用 caseId，不重传素材或另建重复案例。没有案例时，用户对“翻译并保存到镜界”的明确确认可作为新建授权，按新案例流程保存。
2. 已有外文原文备份时先核对并复用，不把此前保存的中文译文误当成作者原文。全文直接按已核实的完整原文翻译，不能用分段重拼或摘要代替；前文、每条时间行的 text、后文与全文中的对应译文保持一致。
3. 逐段翻译全部已获取内容，包括全文、前文、每条时间行的标题与正文、后文；不摘要、不漏段、不新增创作条件。保留原有段落顺序、时间标记和时间行 `start/end` 的原始精度，不按实际镜头重新分配。术语、品牌、型号、数值及单位保持含义准确，完整保留负向条件、音频要求和末尾约束；原文缺失的内容不补造，明确说明译文的实际覆盖范围。没有时间结构时只翻译全文，其余字段保持原有空值；图片仍只使用完整提示词。
4. 需要保存时，调用 `jingjie_save_prompt_translation`，将 `prompt`、`promptPrefix`、`promptLines`、`promptSuffix` 四字段整组传入 data；无内容的字段用空字符串或 []，修改时沿用未改部分。译文独立保存到 `promptTranslation`，不修改原文；字段规则以当前工具 schema 为准。
5. 保存回执不含译文正文。按第3节读取 `data.promptTranslation`，逐字比对全文、前文、后文及每行 text，核对时间行数量和全部 start/end 值，并确认原文未被改写。按第7节处理缺失、差异和失败，核对一致后才报告译文保存完成。

## 6. 镜头、人物与分类字段

每条镜头的概述、分析和固定选项分开保存。先确认画面判断所属的分析维度，再选择字段；字段合法性与语义正确性均须满足，单个固定值不能替代完整分析。当前主要映射如下；如新版本变更，以最新 taxonomy 和工具 schema 为准。

| 原始拉片资料 | 模块／网站字段 |
| --- | --- |
| 原视频、真实时长、测量参数 | save_media_info.data.src、durationSeconds、metadata.width／height／fps／hasAudio |
| frame、可见内容 | save_shot.data.summary |
| size、camera | facts.景别、facts.运镜，仅填对应合法固定值 |
| 构图、光影选项 | facts.构图、facts.光影，仅填对应合法固定值 |
| 长段景别、运镜、构图、光色说明与 note | analysis:[{label,text}]；叙事作用可用 narrative |
| rhythmNote | narrative；不能塞进只接受固定选项的 rhythm |
| audio 中来源提供的台词 | dialogue；助手声音分析放 sound，不混作原始台词 |
| transitionIn | transition，仅填合法固定值，详细衔接依据放 analysis |
| 人物 description／备注 | save_cast_member.data.note；人物图片用 image |

镜头其他资料按需保存 start、end、image、endImage、title、category、rhythm、transition、onscreenText、sound、imagePrompt、videoPrompt。未知台词、模型参数及镜头提示词省略；不生成替代尾帧，不把整片作者原文复制为每镜提示词。

- 景别、运镜、构图、光影只放 facts，不再同时写进镜头 tagValues。固定字段不能接长句或自行拼接多个选项；单选字段仅在同一分析维度内取有依据的主导值，并在 analysis 解释镜内变化，无法确定则省略。不同维度可各自成立，不因单选限制删减其他有依据的判断。
- 案例 type／emotion／lighting／movement、镜头 category／rhythm／transition 及分组值按各自字段规则选择。镜头 tagValues 只用 shotFields 允许的分组，不将案例全部分类直接继承给每个镜头。
- 案例 tags 是补充标签，提示词概念缺项时按第6.1节处理。其他分类也须有依据，不推测制作模型或为了填满字段随意选项。
- 映射须保持含义和分析维度一致。选用有证据支持的上位类别时，保留更具体的判断并说明粒度差异；仅有表面相似或属于另一维度的选项不能代替原判断。没有准确选项时，在支持该含义的合法标签或 analysis 中保留原判断，并说明哪个字段无法准确表达；不把库中缺项改写成画面结论。
- 确需新增全局分类库选项时，先查同义项、确认维护授权及新增能力；没有能力就说明具体缺口，不造分类标识。案例补充标签不属于维护全局分类库，已获案例保存或归类修改授权时直接按第6.1节处理，无需额外索要建库授权。修改既有记录时，不为绕过字段限制而自动清空原值；只有用户要求替换／清除，或核验证明原值错误时，才在本次授权范围内修正并说明原因。合理的未知留空与因工具失败未完成归类要明确区分。
- subjects 仅引用已保存人物 ID；可提前录入人物，或在人物保存成功后回到同一镜头补关联。不要为补资料重建人物或镜头。
- 删除、重排仅在任务要求时进行。删除使用 `jingjie_delete_shot`／`jingjie_delete_cast_member` 与 itemId、当前 revision；仍被 subjects 引用的人物先解除或调整引用。不要用省略对象或空数组暗示删除。

### 6.1 提示词概念缺项时补充标签

1. 从已核实的提示词原文提取明确、适用于当前案例的标签或分类概念，包含风格、题材、主体、环境、动作和视觉手法等。保留原文依据与适用时间范围；不从助手生成的复现建议推断作者标签，不把“不要／no”等负向排除项当作案例具有的特征。提示词要求不等于实际画面已经实现，差异应在说明或 source 中保留，不能据此直接填入镜头的画面事实。
2. 确认当前 taxonomy 的相关分组与字段选项已完整读取，先找精确项，再比较同义词、近义词、别名和中外文对应表达；读取失败或尚未检查不等于库中缺项。含义、分析维度和概括粒度相符才视为匹配，使用该字段的合法值；匹配成功就不再为同一概念重复添加补充标签。只有字面相似、另一维度或过于宽泛的上位项不算匹配，不能因此丢掉原概念。
3. 没有合适项时，将原概念整理为简短、含义准确的补充标签。只要求归类建议时列出建议；已获保存授权时，必须通过 `jingjie_save_classification.data.tags` 保存，不能塞入固定选项、编造 tagValues 值或只写进 analysis／source。以当前 `caseFields.tags` 和工具 schema 核实自由文本能力及数量、长度限制；不支持保存或超出限制时，明确列出尚未保存的概念和原因，不静默遗漏或声称已完成。现有合法分类继续保留，补充标签不代表已新增全局分类库选项。
4. 修改前读取 `classification`，将新增项与已有 `tags` 合并去重，保留原有无关标签；`tags` 数组整体更新，不能只传新增项覆盖旧标签。沿用当前 revision 保存，随后回读 `classification`，逐项确认新增补充标签存在、原有标签未丢失。仅修改或翻译提示词且未授权重新归类时，仍遵守原有模块范围，不自动写入分类。

## 7. 回读、失败与完成条件

写入前按 [SKILL.md 第3节](../SKILL.md#3-逐镜分析)核对标签依据与内容一致性；不同分析维度的判断须分别核验。

每步比对 savedFields、clearedFields、warnings 和本次预期，再按第3节回读目标内容，确认实际落盘。提示词原文与译文均须比较各自四字段；镜头要核对时间、首尾图、长段分析、固定选项与关联，并检查字段之间是否矛盾。回读一致只证明内容按目标保存，还需上述语义核对。

- 非法字段、枚举或分类值会拒绝本次保存。按错误中的字段路径、原因和合法选项修正，必要时重读 taxonomy／schema，再重试该模块或对象。禁止通过删掉用户要求的内容来换取成功；长段文字改放正确字段。
- 409 时按第3节读取最新目标内容和 revision，对照本次目标合并；不要只替换版本号后重发旧对象。无法确定合并结果时保留冲突并说明，不覆盖他人修改。
- 超时、断线或回执不明确时先按第3节读取目标内容。已生效则继续，否则用确认后的 revision 重试同一 caseId／对象 ID；只有上传批次查 submission status。相同故障且没有新线索时停止重复写入，保留工作记录并报告未完成模块。
- 回读缺失、非预期清空或格式不一致时，继续在该模块修复并回读；不能用“接口返回成功”代替内容一致。其他独立且已授权模块可继续完成。
- 最后读取 summary 确认最新 revision、状态和完成情况。某模块尚未核实，不报告整案已完整保存；summary 不能替代各模块正文的回读核对。

结尾简短报告实际保存的模块、最新 revision、当前状态及可访问入口，明确仍缺的分类或来源。MCP 只改编辑稿；当前 status 即使为 published 或 offline，也不表示本次编辑更新了公开快照，不能声称已经发布。

## 8. 增强分析的时间对应与回读

仅在用户已授权深入分析及相应写入时使用。继续同一 caseId，先读当前 `jingjie://submission-guide`、`jingjie_save_prompt_alignment` 完整 inputSchema 和 `get_draft(section:"prompt_alignment")`；沿用有效的主体、要求、观察与关联 ID，并核实当前文档、媒体及镜头依据版本。整组替换前保留本次范围外仍有效的内容，冲突或结果不明时先回读合并，不能只更换 revision 盲写。

- 原文锚点对应真实源文档；作者预算放预期时间，实际观察另记时间。实际查看过且对目标过程足够密集的有序真实帧序列，可用于核实过程和定位近似区间；在观察说明中注明逐帧回看、非实时播放及未听音。单帧、稀疏样本、作者预算或整镜时长均不能自动扩成事件区间。
- 对有实际片段支持的动态要求，成对保存 `video.range.start/end` 与该要求的 `supports` 关联，时间精度与证据一致，范围只覆盖实际核实的内容。不连续出现时分段保留；`frame.atSeconds`、`expectedRanges`、未关联的观察或仅有 `inconclusive`／`contradicts` 不能替代这条可播放定位的关联。声音未实际试听时不填 audio 证据。
- 部分已见、其余未核记 partial，至少保留真实 `supports`，未核内容可用 `inconclusive` 关联说明；reason 分清支持内容、未核条件与真实反例（若有），不强制补反例，也不能一律降为 unverified。实际接口与分析含义不一致时先核实并在已有授权范围内修正，无法处理则保留真实结论及尚未写入项并明确报告；禁止捏造 `contradicts`、删掉未核条件或把 event 改成 global 来通过校验。完全无适当证据的内容继续 unverified。
- 保存后回读完整增强区块，逐项核对原文、依据、判断、观察与关联，再检查实际可用的 `supports → video.range` 数量及代表区间的起止、对应文字和内容范围。零有效区间时不能声称动态时间对应完成；写入成功、帧引用数或待核项数量都不证明时间联动可用。无需据此输出实现率或整片评分。
- 界面可检查时，选择代表区间抽查进入、区间内和离开时的原文高亮；数据回读与界面实测分别报告。界面不可用就保留该验证缺口，不声称已测试。仅静态对应、负向或无可核实动态事件时如实说明范围，不为凑区间制造支持。
